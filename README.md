# PyMagic

An independent Python IDE engine, modelled on the *behaviour* of PyCharm's Python front-end
(documented from analysis of the shipped product). No JetBrains code is copied; the engine is
written from scratch in C#.

## Stack

| Layer | Tech | Why |
|---|---|---|
| Engine (lexer, parser, resolve, types) | C# / .NET 9 (`src/PyMagic.Core`) | Fast, strongly typed, good for compiler-style code (immutable trees, pattern matching) |
| Server | C# LSP server (`src/PyMagic.Server`, stdio, no dependencies) | One protocol, any editor |
| Host | ASP.NET Core minimal app (`src/PyMagic.Web`) | Serves the UI, a workspace file API and one in-process language server per browser tab over WebSocket |
| UI | TypeScript + Monaco (`web/`, bundled with esbuild) | Mature editor component; Electron/Tauri shell later |

## Layout

```
src/PyMagic.Core/Syntax     Token, Lexer, Ast, AstChildren, Parser
src/PyMagic.Core/Semantics  Scope, Symbol, Reference, Binder, SemanticModel, Builtins
src/PyMagic.Core/Flow       ControlFlowGraph, CfgBuilder, ScopeFlow (reaching definitions), FlowModel
src/PyMagic.Core/Types      PyType, Workspace/ModuleInfo, TypeEvaluator (annotations, classes/MRO/members, calls, inspections)
src/PyMagic.Core/Stubs      minimal builtins.pyi and typing.pyi (embedded)
src/PyMagic.Server          LanguageService (hover, definition, completion, symbols, diagnostics), JSON-RPC/LSP transport; run: dotnet run --project src/PyMagic.Server -- [--typeshed <dir>] [--root <dir>] [--lib <dir>]
src/PyMagic.Web             pymagic-web: static files, /api/info, /api/files, /api/file (GET/PUT, .py only, confined to the root), /lsp WebSocket
web/src                     main.ts (Monaco providers, files, diagnostics), lsp.ts (JSON-RPC client), index.html;  cd web && npm install && npm run build
examples/demo               small project with deliberate mistakes for trying the editor
tests/PyMagic.Tests       dependency-free test runner:  dotnet run --project tests/PyMagic.Tests
                          corpus check:  dotnet tests/PyMagic.Tests/bin/Debug/net9.0/PyMagic.Tests.dll corpus <dir>
```

The test project is a plain console runner because this machine's NuGet only has an offline source
(no xunit). Switch to xunit once nuget.org is configured.

## Roadmap (matches the behaviour notes)

1. **Lexer** - indent/dedent, brackets, continuations, strings (PEP 701 f-strings), numbers. *Done.*
2. **Parser** - recursive descent, statement-level error recovery, soft keywords (`match`, `case`, `type`) resolved by speculative parse, AST with source ranges. *Done; parses all 1037 stdlib files and 404 site-packages files with zero diagnostics.* Still open: f-string interior as expression nodes, store-context validation, finer error messages.
3. **Scopes + name tables** - module/class/function/lambda/comprehension/PEP 695 type-parameter scopes, `global`/`nonlocal`, class-scope visibility, walrus-in-comprehension, match captures, star imports, builtins. Every name use is a `Reference` (read/write/delete) linked to a `Symbol` with its declarations. *Done; builds on the whole stdlib with no crashes, the only unresolved names are runtime-injected ones.* Still open: `__all__`, `try/except ImportError` fallbacks, conditional-definition awareness (needs the control-flow graph).
4. **Control-flow graph + reaching definitions** - one CFG per scope built in evaluation order (branches, loops with `break`/`continue`/`else`, `try`/`except`/`else`/`finally` with the finally block built for both the normal and the exceptional path, `match`, short-circuit `and`/`or`/ternary with separate true/false exits, constant conditions, `del`, `except ... as e` unbinding). Forward bit-set dataflow gives, per use of a local, the bindings that may reach it and whether it may still be unbound. Produces unreachable-code and "referenced before assignment" findings; the whole stdlib (1037 files) analyses in about 2.5 s. *Done.* Still open: `NoReturn` calls (needs types), `with` blocks that swallow exceptions, `break`/`return` running through `finally`, and attribute/member resolution.
5. **Types, attribute and call resolution** - type model (classes/instances, unions, generics with type variables, tuples, callables, modules, `super()`), a lazy evaluator with cycle cutting, annotation evaluation (`Optional`, `Union`, `X | None`, `Callable`, `Literal`, `Tuple`, aliases, string forward references, PEP 695 parameters), C3 MRO with unknown-ancestor tracking, member lookup (class attributes, `self.x = ...` instance attributes, `__slots__`, properties, static/class methods, metaclasses, `__getattr__`), method binding and generic substitution, constructors, overload selection, argument-to-parameter mapping (positional, keyword, `*args`, `**kwargs`, defaults, keyword-only, positional-only) with problems reported, type-variable solving from arguments, lenient assignability (numeric promotion, protocols), operators through dunder methods, iteration, subscripts, destructuring, return-type inference (including generators and coroutines). Library types come from bundled minimal `builtins`/`typing` stubs parsed by our own parser; modules are also loaded from search roots. *Done for the core; 184 tests; the 152 top-level stdlib modules inspect in about 3 s without crashes.* Still open: enum/dataclass/namedtuple/TypedDict synthesis, narrowing (`isinstance`, `is None`, truthiness), call-site parameter inference, `NoReturn`, decorators that change signatures, and real typeshed instead of the minimal stubs.
6. **Narrowing and library providers** - flow-sensitive narrowing (`is None`/`is not None`/`== None`, `isinstance` with classes, tuples and `|`, truthiness, through `not`/`and`/`or`, `assert`, early `return`/`raise`/`continue`, loops, comprehension conditions, ternaries, and attribute chains like `self.x`), assignments that reset or narrow to the assigned value; enums (members, `.value`/`.name`, iteration, lookup by value or name, `auto()`, `IntEnum`/`StrEnum`/`Flag`), dataclasses (constructor synthesis with defaults, `field()`, `init=False`, `kw_only`, `KW_ONLY`, `ClassVar`, `InitVar`, inheritance, generics), named tuples (`NamedTuple` classes, `namedtuple()` and `NamedTuple()` calls: constructor, unpacking, indexing, iteration), and TypedDict (constructor, key access, `.get`, `total`, `Required`/`NotRequired`). Bundled stubs now also include `enum`, `dataclasses`, `collections` and `abc`. *Done; 209 tests.* Still open: attrs/pydantic/`dataclass_transform`, functional `Enum()`/`TypedDict()` forms, literal and enum-member comparisons (`x is Color.RED`), `type(x) is C`, `callable()`, `hasattr`, and `in`-narrowing.
7. **Typeshed, stub packages and `py.typed`** - modules resolve in this order: source roots (user code, `.pyi` before `.py`), stub packages (`foo-stubs`), inline typed packages (`py.typed`), typeshed (standard library gated by `stdlib/VERSIONS` for the configured Python version, then third-party `stubs/<dist>`), library sources, namespace packages. Partial stub packages (`py.typed` containing `partial`) and partial typeshed distributions (`partial_stub = true`) fall through to the real library for modules they do not contain. Branches decided by the interpreter (`sys.version_info`, `sys.platform`, `TYPE_CHECKING`) are not bound, so stubs define exactly the names that exist for the configured version and platform. Star imports and `__all__` are followed (`collections.abc` is one star import). Real `builtins.pyi`/`typing.pyi` work: special forms are recognised by name, `TypedDict`/`Generic`/`Protocol` are special forms, `__x` positional-only parameters, structural (protocol) type-variable solving. Point `WorkspaceOptions.TypeshedPath` at a typeshed checkout (the tests use the copy inside a PyCharm installation, or `PYMAGIC_TYPESHED`); without one the small bundled stubs are used. Typeshed itself is not copied into this repository (its licence travels with it). *Done; all 223 tests pass with both the bundled stubs and real typeshed; the 152 top-level stdlib modules inspect in about 9 s against typeshed.* Still open: `site-packages` discovery from an interpreter, `.pth` files, `__init__.pyi` re-export rules for `import a as a`, conditional re-exports through `__all__ +=`, stub `@overload` evaluation of explicit `self` annotations, and caching parsed stubs on disk.
8. **Language server** - `pymagic-server` speaks LSP over stdio (own JSON-RPC framing on System.Text.Json, no packages): full-text document sync, `publishDiagnostics` (syntax errors, unresolved names, unreachable code as a faded hint, possibly-unbound locals, call/attribute findings), `hover` (declaration-style signatures such as `def f(a: int) -> str`, `class B(A)`, `(parameter) a: int`, inferred variable types with narrowing), `definition` (locals, defs and classes, imports followed to the defining module, attributes through the MRO and `self.x` sites, `import a.b` to the module file), `completion` (members of any value including unions, class vs instance attributes, inherited members, module members; scope-aware names, builtins and keywords; works while the line is still a syntax error, and on a fresh indented line after a body), and nested `documentSymbol`. Open buffers shadow files on disk; module names come from the workspace folders (`SourceRoots`). Initialization options: `typeshedPath`, `libraryRoots`, `reportTypeMismatches`. 30 tests (253 total; they pass with the bundled stubs and with real typeshed) plus a stdio smoke test of the built executable. `references`, `prepareRename` and `rename` run over the whole project (open buffers plus every .py file under the workspace folders): names resolve through the scope tables and through `from m import x` chains (an `as` alias keeps its local name), attribute usages (`obj.attr`, `Class.member`, `module.name`, `self.x` sites) are matched by the receiver type so same-named members of other classes are left alone, and renames refuse library symbols, keywords and name clashes. 15 more tests (268 total). `codeAction` offers quick fixes keyed on diagnostic codes: for an unresolved name `Import 'x' from 'm'` (project modules first, then common standard-library modules; merged into an existing `from m import ...`, placed after the leading import block and docstring), `Import module`, `Add self.` when the name is a member of the enclosing class (also for `count += 1` that made it local), `Change to` for a misspelled name or attribute (edit distance scaled by length), `Create function` from a call; `Remove unreachable code`; and the new `Unused import` hint (faded; names in string annotations and `__all__`, `__future__`, star imports and package `__init__` modules count as used) with `Remove unused import` and a bulk `Optimize imports` (`source.organizeImports`); deleting the only statement of a block leaves `pass`. 16 more tests (284 total). Still open: file watching (files changed outside the editor are noticed at the next edit, see item 12), overriding methods (renaming a method does not rename its overrides), star imports, strings and `__all__`, signature help, semantic tokens, code actions, `didChangeConfiguration`/file watching, cancellation, and UTF-8 position encoding negotiation.
9. **Monaco UI** - `web/` is a TypeScript app (Monaco 0.52, esbuild bundle, no framework): file list for the workspace folder, one model per file all opened in the server so cross-file diagnostics and navigation work, debounced full-text sync, markers from `publishDiagnostics` (unreachable code is faded), hover, completion on `.` and while typing, go to definition across files (F12 / Ctrl+click, opens the target file), Shift+F12 find usages and F2 rename across files (verified in the browser), lightbulb quick fixes (Ctrl+.), outline (Ctrl+Shift+O), Ctrl+S saves through the file API, dirty markers and an error/warning count in the status bar. Run: `cd web && npm install && npm run build`, then `dotnet run --project src/PyMagic.Web -- --root <project dir> [--typeshed <dir>]` and open http://127.0.0.1:5180/ (the host binds to localhost only and has no authentication). Verified in the built-in browser against `examples/demo`: diagnostics, hover, F12 into another file, member completion. Still open: automated UI tests, new/rename/delete files, tabs, find in files, signature help, a search for the typeshed path, an Electron or Tauri shell.

10. **Run and debug** - `PyMagic.Server.RunSession` starts the configured interpreter (`--python`, `PYMAGIC_PYTHON`, else `python`) on a script in the workspace folder (working directory and `PYTHONPATH` = the folder), streams stdout and stderr as they arrive, forwards stdin, and kills the process tree on stop. Debugging uses `pm_debug.py` (embedded in the server assembly and written to the temp folder when needed): a small debugger built on the standard `bdb` module, no packages to install, which connects back over a localhost socket with a one-time token and speaks JSON lines. Features: line breakpoints (set before the run, and changeable while the program is stopped), continue, step over, step into, step out (lands in the caller right after the call returns), call stack, Locals and Globals with lazily expanded lists, dicts, sets and object attributes, an evaluate console that also accepts statements, a stop on an uncaught exception with the traceback frames for inspection, and "just my code" stepping (library frames are skipped). The web host adds `/run` (WebSocket) and `/api/interpreter`. The UI has a toolbar (Run, Debug/Resume, Stop, Step over/into/out), red gutter breakpoints that survive reloads (F9 toggles), the current line and arrow, an Output tab with an input line, and a Debugger tab (frames, variables, evaluate). Keys: F5 debug or resume, Ctrl+F5 run, Shift+F5 stop, F10/F11/Shift+F11 step. 10 more tests (294 total; they run real Python and are skipped when none is on the PATH) and a browser check on `examples/demo/checkout.py`. Still open: pausing a running program, breakpoints added while a long-running frame is already executing only take effect in new calls, conditional and log breakpoints, watches that persist between stops, debugging threads other than the main one, run configurations (arguments, environment, working directory), a pytest/unittest runner, virtualenv discovery, attaching to a running process.

11. **Test runner** - `TestDiscovery` finds tests without importing anything: it parses `test*.py` / `*_test.py` files and applies pytest's and unittest's rules (functions and methods starting with `test`, classes named `Test*` without `__init__`, any class deriving from a `TestCase` including through base classes of the same file and inherited test methods), giving ids like `tests/test_cart.py::TestLabels::test_label_has_name`. `RunSession.StartTests` runs the embedded `pm_tests.py` with the project's interpreter: pytest when it is installed (unittest tests run under it as well), otherwise the standard unittest runner (with a note that pytest-style functions need pytest). It reports over a localhost socket: `collected` (including parametrized cases such as `test_many[2-3]`), `testStarted`, `testResult` (passed, failed, error, skipped, xfailed, xpassed, with duration, message, traceback, captured output and the failing file and line) and `collectError` for import and syntax errors in test files; the host waits for the last messages before it reports the process exit. The web host adds `/api/tests` and a `startTests` message on `/run`. The UI has a Tests tab: a tree with status icons that roll up to files and classes, play buttons on every row, Run all / Run selected / Run at cursor (Ctrl+Shift+F10) / Re-run failed, a framework selector (auto, pytest, unittest), a summary line, a details pane with the message, traceback and captured output with a "Go to file:line" link, red error markers in the editor at failing lines, and the runner's console output. `examples/demo/tests` has passing, failing, skipped and parametrized tests in both styles. 10 more tests (304 total): discovery rules, every unittest outcome, selection by id, import errors, and the pytest paths (skipped when pytest is not importable; run once against a throwaway virtualenv with pytest 9.1). Still open: debugging a test, tests defined in classes whose bases live in other files, pytest fixtures and markers in the tree, running with coverage, a gutter run icon next to each test, stopping a test run from the UI, `unittest` subtests as separate nodes, and watching the disk for new test files.

12. **Incremental analysis** - three layers keep an edit cheap. (1) `AnalysisCache` (Core) keeps parsed and bound modules between workspaces: library and project files are reused while their modification time and length are unchanged, editor buffers while their text is identical, bundled stubs and the resolver's tables (typeshed `VERSIONS`, third-party stub index) for good; it is dropped when the search paths or the target Python version change. A new `Workspace` is then just a fresh type evaluator whose caches fill lazily, so nothing evaluated before an edit can leak into the result after it, and only the edited file is parsed again. (2) The server loop (`Server.Pump`) takes every waiting message at once, drops a full-text edit when a later edit of the same document is queued behind no request, answers requests first, and publishes diagnostics only when the queue is empty. (3) Diagnostics are recomputed for the edited documents and the open documents that import them, directly or through files that are not open (`LanguageService.DependentsOf`, from a cached per-module import list), and are published only when they differ from what the client already has; closing a file refreshes its importers. Measured with `dotnet tests/PyMagic.Tests/bin/Debug/net9.0/PyMagic.Tests.dll bench <root> <file> [edits] [open files]` against typeshed (debug build): on the demo project diagnostics after an edit went from 94 ms to 5 ms, on a 3,000-line stdlib module with 16 files open from 335 ms to about 105 ms, completion from 61 ms to 14 ms, a repeated project-wide find usages from 2.3 s to about 0.1 s (the first one still parses every file once); in the browser 29 keystrokes sent at once produced two analyses instead of 29. 10 more tests (314 total). Still open: parsing only the changed region (the edited file is still lexed, parsed, bound and inspected as a whole), keeping evaluated types of unchanged modules across edits, file watching, evicting old buffer versions, and running the evaluator off the message thread so a long analysis can be cancelled.

13. **Interpreters and virtual environments** - `InterpreterDiscovery` finds interpreters without running them, in order of preference: virtual environments of the project (`.venv`, `venv`, `env`, `.env`, `virtualenv` in the project folder and up to two folders above it, and any folder with a `pyvenv.cfg` directly inside the project), `VIRTUAL_ENV` and `CONDA_PREFIX`, `python` on PATH, the Windows `py` launcher's list, and the usual homes of python.org, uv, pyenv and conda installs; the empty Microsoft Store aliases are skipped and one installation is listed once. `InterpreterInspector` runs a candidate once in isolated mode and reads its version, implementation, `sys.platform`, prefix and base prefix (so virtual environments are recognised), standard library folder and `sys.path`, which includes site-packages and everything `.pth` files add; answers are cached until the executable changes or a package or `.pth` file is added to its site-packages. `InterpreterManager` keeps the project's choice in `.pymagic/settings.json` (a folder that ignores itself in git), falls back to the best discovered interpreter when none was chosen or the saved one is gone, lists all working interpreters in parallel, and creates `.venv` with the selected interpreter (it refuses to overwrite). The choice drives everything: the language server follows the interpreter's Python version and platform (so `sys.version_info` and `sys.platform` branches are decided for it) and searches its site-packages, `.pth` entries and, when a typeshed is configured, its standard library after typeshed, for stub packages, `py.typed` packages and library sources; run, debug and the test runner start that interpreter; switching it republishes the diagnostics of every open file. LSP: `initializationOptions.pythonPath`, and `workspace/didChangeConfiguration` with `settings.pymagic.pythonPath` (empty string: back to the defaults). Host: `GET /api/interpreters`, `GET`/`POST /api/interpreter`, `POST /api/venv`; `--python` overrides the choice for one run. The toolbar has an interpreter picker and a "+ venv" button. 13 more tests (327 total), among them real virtual environments with a package and a `.pth` module that the editor must resolve. Still open: editable installs that use import hooks instead of `.pth` files (`__editable__` finders), installing and listing packages from the UI (pip), choosing an interpreter per file or per run configuration, remote interpreters (WSL, SSH, Docker), and conda environments that are not activated being found by name only under the default install folders.

14. **Packages panel** - `PackageManager` asks the project's own interpreter's pip: the installed packages (`pip list --format=json`, with editable installs marked), details (`pip show`: summary, home page, licence, location, requires, required by) and newer releases (`pip list --outdated`, on request). Installing, upgrading and uninstalling run as `python -m pip ...` through the run socket (`startPip`), so the output streams into the panel; `ensurepip` repairs an environment created without pip. The host never forwards raw arguments: it builds the command from an operation (`install`, `uninstall`, `installRequirements`, `ensurepip`), package specs that match a strict pattern (no options, spaces, paths or URLs) and, for requirements, only files that the project scan lists. `RequirementsScanner` reads `requirements*.txt` (also a `requirements/` folder; comments, options, URLs, extras and environment markers handled) and the `[project] dependencies` and `optional-dependencies` of `pyproject.toml`; the panel shows how many of each file are installed and offers "Install missing". Typing a name asks PyPI for the latest version and summary (cached, optional: it works without a network), and `--user` is offered for system interpreters. After every install or uninstall the host re-reads the interpreter and tells every open editor, so imports of new packages resolve (and removed ones stop resolving) without a restart. Uninstall needs two clicks, and pip, setuptools and wheel cannot be removed from the UI. Because installing a package runs code, the host now refuses WebSocket upgrades and POST/PUT requests whose `Origin` is not its own page and any request with a foreign `Host` header (web pages can otherwise reach localhost, and DNS rebinding could hand them the API). 9 more tests (336 total): name normalisation and the spec filter, both file formats, a real virtual environment with real pip installing and removing a locally built wheel, `ensurepip` repairing an environment, and the editor resolving a package after it is installed and no longer after it is removed. Browser check on `examples/demo` in a throwaway `.venv`: install by name with the PyPI hint, details, two-step uninstall, "Install missing" from `requirements.txt` (pytest), "Check updates", and the Tests tab then running under pytest. Still open: extra index URLs and proxies, installing from a path or a git URL (refused on purpose until there is a confirmation step), version pickers, dependency trees, an "Install package" quick fix for unresolved imports (needs an import diagnostic first), lock files (uv, poetry, pip-tools), and conda or uv-managed environments (pip is used for all).

15. **Unresolved imports** - with an interpreter selected, imports are checked against what that interpreter would find. `import a.b.c` and `from a.b import c` report the first missing module (`No module named 'a.b'`, on the module name), `from m import n` reports names the module does not have (`Cannot import name 'n' from 'm'`) unless the module can create names dynamically (`__getattr__`, star imports, `globals()`, `sys.modules`, `setattr`), and a module that only typeshed knows (third-party stubs, or `typing_extensions`) is reported as `Package 'yaml' is not installed` because the editor can complete it but Python cannot import it. What is not reported: the standard library (the interpreter lists its own module names, so this works without stubs), extension modules (`.pyd`/`.so` files), imports under `try:` with a handler for `ImportError`, `ModuleNotFoundError`, `Exception` or a bare `except`, imports in branches that the interpreter's `sys.version_info` or `sys.platform` rules out, `_typeshed`, a stubs-only import under `if TYPE_CHECKING:`, and nothing at all while no interpreter is selected. Editable installs made with setuptools' import-hook finders (`__editable___*_finder.py` and its `MAPPING`) are read, so such packages resolve; the folder of a script that lies outside every configured root counts as a root (Python puts it on `sys.path`). Quick fixes: `Install package 'X'` (a command, not a text edit) for a missing top-level module or an uninstalled package, using the package the project declares in `requirements*.txt` or `pyproject.toml` when there is one, else typeshed's stub distribution name (`yaml` -> `PyYAML`), else a table of the usual differences (`PIL` -> `Pillow`, `cv2` -> `opencv-python`, `sklearn` -> `scikit-learn`, `bs4`, `dateutil`, `dotenv`, `jwt`, ...), else the module name; and `Change to 'x'` for typos among the standard library, the project's modules, installed top-level names and a module's own names. The page registers the `pymagic.installPackage` command, which opens the Packages tab and runs pip; when it finishes the interpreter is re-read and every open file is checked again, so the warning disappears. Codes on the diagnostics: `unresolved-import`, `unresolved-import-name`, `package-not-installed`. 15 more tests (351 total), including real interpreters, a clean virtualenv for the stubs-only case, compiled modules, guarded and dead imports, and the server round trip; the existing install/uninstall test also checks that the warning follows the package in and out. Browser check on `examples/demo/config_loader.py` in a throwaway `.venv`: the three diagnostics, `Change to 'Product'` applied, `Install package 'PyYAML'` installed it and cleared the warning. Still open: asking PyPI whether a suggested package exists before offering it, an install command for LSP clients other than the PyMagic page (`workspace/executeCommand`), import cycles and `__all__` checks, namespace-package corner cases, and remembering "ignore this import" choices.

16. **Refactorings** - available from the lightbulb (Ctrl+.), the refactor menu, and the shortcuts Ctrl+Alt+V / C / M / N. The server offers each as a code action of kind `refactor.extract.*`, `refactor.inline.variable` or `refactor.rewrite` that carries the command `pymagic.refactor`; the page asks for a name (suggested from the expression and never one that is taken), sends the custom request `pymagic/refactor` and applies the returned edits as one undo step. Every request returns a complete set of edits or fails with the reason, which the page shows. **Extract variable** (this occurrence, or all of them when the expression is free of calls and its names do not change in between): inserted above the statement with its indentation; refused for assignment targets, lambdas and comprehensions, `while` conditions, `elif` conditions, a statement that shares its line, and taken or invalid names; redundant parentheses in the selection go with it and multi-line values are parenthesised. **Extract constant**: module level, after the docstring and imports, or just before the first use when it reads other module names; refused for locals and calls; optionally replaces every identical copy. **Extract method**: from whole statements or one expression; parameters are the names the selection reads that already had a value (decided with the reaching definitions, so a name first assigned inside it is not one), results are the names it assigns that are read afterwards (`a, b = new(...)`), names used inside f-strings count, lines inside multi-line strings keep their text; in a class it becomes a method (`self.` calls, `@staticmethod` and `@classmethod` respected), in a function or at module level a function placed after the function or before the statement, `async` when the selection awaits; refused for `return`, `yield`, `global`/`nonlocal`, assignments to outer scopes, a `break` or `continue` whose loop is not part of the selection, `await` outside an async function, and class bodies. **Inline variable**: a single plain assignment whose uses all see only that assignment (checked with reaching definitions), the value's names unchanged afterwards, uses in the same scope, parentheses only where precedence needs them; a value with calls may move only to a single use in the next statement; an unused variable is removed (the call is kept); refused for module variables used by other files and for names that appear inside f-strings. **Safe delete**: functions, classes, plain variables and imports; refused with the number and places of the usages (also in other files), for mentions in f-strings or in `__all__`, and for values with calls. 36 more tests (387 total): text in / text out for every refactoring and every refusal, the menu and the code actions, the server round trip, and a behaviour check that runs the original and the refactored program with real Python and compares what they print. The parser still keeps f-strings as text, so names inside them are looked up in that text; refactorings refuse rather than guess. Browser check on `examples/demo/report.py`: extract method on the loop (parameters `cart, total, names`, result `total`), extract variable with the prompt, and the "already defined" refusal. Still open: move, introduce parameter and field, extracting a `return`-ing or `yield`-ing block, renaming the new name right after extracting, a preview of the changes, and refactorings across several files.
17. **Change signature and inline method** - both work across files. **Change signature** (Ctrl+F6, or *Change signature…* in the refactor menu, on a function definition or on a call; a class gives its `__init__`) opens a dialog with the parameters: rename, retype (positional-only, normal, keyword-only, `*args`, `**kwargs`), default, reorder, remove, and add with the value that existing calls should pass. The function can be renamed at the same time. The server (`pymagic/signature`, `pymagic/changeSignature`) finds every call through the project-wide usages (aliases, constructors, `super().__init__`, methods), maps each argument to its parameter and rewrites the call; the header keeps its layout, parameters renamed in the body, and warnings list what could not be rewritten (calls with `*`/`**` arguments, references that are not calls, overriding methods, comments). It refuses decorated functions (other than `staticmethod`/`classmethod`), library functions, invalid orders, a removed parameter that is still used, and names that would clash. **Inline method** (*Inline method (this call)*, Ctrl+Alt+P, or *Inline method and remove it* when every use is a call): bodies with one trailing `return` or none; parameters are substituted, or bound to temporaries when an argument has side effects or is used several times; locals are renamed on a clash; the result takes parentheses only where precedence needs them (inline variable uses the same logic now). It refuses async functions, generators, nested defs/classes, `global`/`nonlocal`, `*args`/`**kwargs`, and constructors. Renaming/usages from a *use* of an imported name now reach the definition. 41 more tests (428 total): text in / text out, refusals, and behaviour checks that compare the program output before and after with real Python.
